# SOUWERS: формуляр 2.7.0

Готовые файлы для существующего формуляра в кабинете SOUWERS. Базовая версия — предоставленная v2.6.0. Исходные загрузки сохранены отдельно в `archive/input-2026-11-03/`.

Комплект для установки: `releases/souwers-formulary-v2.7.0.zip`. Он содержит три готовых файла, два блока Tilda и инструкцию.

Все файлы отдельно с полными именами и нумерацией T123 — в папке `files/`. Для обновления формуляра нужны JS/CSS версии 2.7.0, мост кабинета 1.0.3 и два T123 `block-1` / `block-2`. Файлы меню Premium 1.0.0 приложены без изменения исходного JS; они нужны только при первоначальной установке этого меню.

## Установка в Tilda

1. Загрузите в прежнюю папку `scripts/` хранилища **все три** файла из `scripts/`:
   - `souwers-formulary-v2.7.0.js`;
   - `souwers-formulary-v2.7.0.css`;
   - `souwers-account-formulary-v1.0.3.js`.
2. Дождитесь доступности новых адресов. Замените существующий первый блок формуляра содержимым `tilda/01-formulary-template.html`, второй — содержимым `tilda/02-formulary-loader.html`. Это замена существующих блоков, не добавление ещё одной копии.
3. Опубликуйте страницу кабинета и обновите её. Шаблон по-прежнему монтируется существующим кабинетом после проверки Premium.

В этой доработке не требуется замена Premium Navigation 1.0.0, PDF-модуля 1.0.0 и основного блока кабинета 1.8.33. Скрипт моста 1.0.3 нужен вместе с новым формуляром: он передаёт документ родительской корзины, чтобы корректно подавлять её автооткрытие и отправлять события обновления.

Комплект подготовлен для ручной установки. Загрузка в хранилище и публикация Tilda в рамках этой работы не выполнялись.

## Что изменилось

- У всех 42 предустановленных нот разные SVG. В том числе различаются бергамот, цитрус, апельсин, грейпфрут, лайм, древесный, сандал, кедр, ветивер, сено и зелёные ноты. Кокос получил собственный рисунок.
- Поле аромата начинается пустым, подпись — «Придумай название аромата». Старые стандартные названия убираются из поля; своё сохранённое название остаётся.
- Обложки корректно разрешаются внутри `iframe srcdoc`: используется `document.baseURI`. Поддержаны обложка варианта, галерея и основное изображение товара. Пустой адрес больше не превращается в адрес главной страницы.
- Таблица обновляет существующие строки и элементы управления. Кнопки корзины и активные поля не пересоздаются при каждом движении ползунка. Убрана мигающая анимация строк, видимость кнопок при ожидании корзины сохраняется.
- Значения «Взвесить, г» имеют одинаковое число знаков после запятой с учётом шага весов и выровненные цифры. Изменено только отображение.
- Компоненты можно свернуть по нотам или свернуть все ноты. Итоговые доли, навески, экспорт и заказ учитывают весь состав независимо от сворачивания.
- Порядок смешивания сохранён. Если одна нота встречается в нескольких последовательных группах из-за кристаллов, переключение сворачивает все группы этой ноты.
- Компактная панель долей находится в начале конструктора и остаётся под заголовком при прокрутке. В ней видны растворители, база, сердце и верх, а также полоса баланса.
- Изменение доли в закреплённой панели раскрывает ноту, подсвечивает её компоненты и прокручивает **только окно конструктора** к первому компоненту. Непрерывное изменение ползунка не повторяет прокрутку на каждом шаге.

## Разработка и сохранение

Редактируемый код — в `src/`, готовые файлы — в `scripts/`. Для сборки: `npm ci`, затем `npm run build` и `npm run check`. Минификация не меняет имена и не выполняет оптимизацию вычислений.

Для браузерной проверки нужны Python Playwright и Chromium: `npm run test:browser`. Используются тестовые материалы и перехват всех запросов; настоящие заказы не создаются. Подробности проверки — в `docs/verification.md`.

Чтобы работа пережила замену среды, сохраняйте изменения коммитом **и отправляйте ветку на GitHub**. Создание новой ветки само по себе не сохраняет незакоммиченные файлы. После запуска другой среды можно получить эту же ветку из репозитория, вместо повторной сборки проекта с нуля.
